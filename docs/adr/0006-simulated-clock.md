# ADR 0006: One simulated clock, read by nothing but the clock hook

**Status:** accepted

## Context

ADR 0001 keeps propagation in the browser so that "the current or simulated timestamp" can be propagated locally, and `docs/ARCHITECTURE.md` reserves Phase 2 for one canonical simulated timestamp that components must not offset independently. Before P2-02 the app had three clocks that only happened to agree: `useIssTracking` ran its own `setInterval` and read `new Date()` per tick, `useStarlink` ran another and sent `Date.now()` to the worker, and the ground track refreshed on a third. A time control bolted onto any one of them would have desynchronised the others: the marker at T+90 while the track was still drawn around now, or the Starlink shell a second behind the ISS.

## Decision

- `lib/simulatedTime.ts` owns the numbers: `MAX_OFFSET_MS` (±90 minutes), `OFFSET_STEP_MS` (10 minutes), `clampOffset`, `simulatedAt`, and the two readouts. A non-finite offset clamps to live rather than becoming a `NaN` instant.
- `hooks/useSimulatedClock.ts` is the only consumer-facing clock. It reads real time through the existing 1 Hz `useClock`, adds the clamped offset, and exposes `at` (ms epoch, `null` until mounted so server and client markup agree), `offsetMs`, `live`, `setOffsetMs` and `reset`.
- Every orbital consumer receives `at` and nothing else: `useIssTracking(at)` propagates the marker in an effect keyed on it, recomputes the ±45-minute track when the centre drifts 60 s from the last one, and restarts the altitude sparkline on any non-contiguous jump; `useStarlink(enabled, at)` posts each `at` to the worker, which already took an absolute epoch under ADR 0005. Neither hook reads a clock any more; the one timer left is the 200 ms trailing debounce on the track recompute, which delays work but never decides the instant. Restarting the sparkline on a scrub collapses it to a single point until a minute of contiguous fixes has accrued; that is the honest chart for a jump.
- `lib/simulatedTime.test.ts` asserts on the source of `hooks/useIssTracking.ts`, `hooks/useStarlink.ts`, `workers/starlink.worker.ts`, `components/Globe/GlobeScene.tsx`, `components/dashboard/OrbitalDashboard.tsx` and `components/dashboard/TimeControl.tsx` that none contains `Date.now()` or `new Date()`. It is a fitness function, not a unit test: the property it protects — one clock — is invisible to any test of a single module.
- The control is a native `<input type="range">` (−90..90 minutes, `aria-valuetext` in words) with ±10-minute buttons and a "Return to now" action, rendered in flow under the globe rather than over it so the 375 px viewport keeps the Starlink toggle, the legend and the slider from colliding.
- Launch countdowns, the top-bar clocks and the 72-hour pass forecast (`lib/passes.ts`, `PassPanel`) stay on real time. The objective scopes simulation to the ISS, its tracks and Starlink; a countdown to a real launch has no meaningful simulated reading, and a forecast is by definition measured from now. "One canonical time source" therefore means one clock for everything orbital that is drawn, not one clock for every number on the page; the enforced boundary is the file list in `lib/simulatedTime.test.ts`. The clock is represented as an offset from real time, never as an absolute instant, so it keeps ticking while scrubbed and returns to live by clearing the offset.

## Consequences

Positive: the marker, track, Sun state and Starlink shell are computed for the same instant by construction, which `e2e/time-control.spec.ts` checks by capturing the worker's `propagate` requests and comparing them with the instants the dashboard rendered. Adding a fourth consumer means accepting `at`, and the fitness test fails the build if it reaches for a clock of its own. The dashboard already re-rendered at 1 Hz on every ISS position; the clock tick adds one render per second ahead of it, which is the cost of a single source of truth.

Negative: scrubbing the slider recomputes the track once per minute of travel (about 180 propagations and one `pathsData` rebuild each), held behind a 200 ms trailing debounce so a drag pays once when the pointer pauses. The ISS marker is re-created rather than tweened on any non-contiguous fix: a 90-minute jump would otherwise glide across the globe for a second, and merely zeroing the transition is defeated by the previous fix's still-running tween; the cost is one marker element rebuilt per scrub step. The fitness test is coupled to the literal spellings `Date.now()` and `new Date()`; a consumer that smuggled a clock in through another API would pass it, so it guards the common mistake, not every mistake.
